# Chapter 3: Methodology

This chapter describes how the research was designed and carried out: the philosophy and approach, the dataset and pre-processing, the standardised experimental framework, the models, the evaluation metrics, the Grad-CAM and EAA-IoU formulation, the design of the Streamlit application and the ethical considerations.

## 3.1 Research Philosophy and Approach

The research follows a positivist philosophy, informed by critical realism. It seeks objective, measurable evidence about the relative effectiveness of different classification approaches, while recognising that medical images reflect a complex reality that no single metric captures completely. Following the Research Onion model used in the Interim Report, the approach is deductive: hypotheses H1 to H3 were stated before the final experiments and are tested against quantitative results. The strategy is experimental. Every model is trained and evaluated under the same controlled conditions, so that differences in performance can be attributed to the model rather than to the pipeline.

The Interim Report planned a mixed-methods design that would add qualitative feedback from healthcare professionals. Within the time and access available, this qualitative strand could not be completed; the study is therefore quantitative, and a clinician evaluation of the prototype is proposed as future work (Section 6.4).

## 3.2 Dataset

The study uses the public Brain Tumor MRI Dataset (Nickparvar, n.d.), which contains two-dimensional T1-weighted, T2-weighted and FLAIR slices in JPG format, in axial, coronal and sagittal planes. The version used here contains 7,200 images in four balanced classes, divided by the dataset authors into a Training folder and a Testing folder (Table 3, Figure 2). The Testing folder was held out completely and used only once, for the final evaluation.

**Sampling.** The training folder was divided into training and validation subsets with a 90:10 split (5,040 and 560 images) using the Keras directory loader with seed 42. Because the four classes are equally represented, this preserves an approximately equal class balance, in line with the stratified sampling principle stated in the Interim Report.

## 3.3 Pre-processing

Pre-processing was deliberately minimal and identical for all models of the same type:

- **Resizing.** Images were resized to 256 × 256 pixels for the standalone deep models and to 128 × 128 pixels for the feature-extractor networks. The smaller size for feature extraction keeps the classical stage computationally manageable.
- **Normalisation.** Pixel values were divided by 255, giving a range of [0, 1] for every model. This replaced the inconsistent normalisations (for example [−0.5, 0.5]) found in earlier prototype notebooks during the Interim stage.
- **Colour.** Deep models received three-channel images. For the raw-pixel classical baseline, images were read in greyscale and flattened to 65,536 features (256 × 256).
- **Labels.** Integer class labels were used with sparse categorical cross-entropy throughout, replacing the mixture of integer and one-hot encodings in the prototypes.

No data augmentation, cropping or other image enhancement was applied, so that the comparison reflects the models rather than the pre-processing.

## 3.4 Standardised Experimental Framework

A central finding of the Interim Report was that the original prototype notebooks used different image sizes, normalisations, label encodings, batch sizes and train/test splits, which made their results incomparable. All experiments in this report were therefore re-run from a single notebook with one shared configuration (Table 4).

| Setting | Value |
|---|---|

| Input size, feature extractors | 128 × 128 × 3 |
| Pixel scaling | [0, 1] (divide by 255) |

| Test set | Official Testing folder, 1,600 images, used once |
| Batch size | 32 |
| Optimiser and loss | Adam (default learning rate 0.001), sparse categorical cross-entropy |
| Epochs | Custom CNN 20; InceptionV3, Xception and the three feature extractors 10 |
| Random seed | 42 (Python, NumPy and TensorFlow) |
| Hardware and software | Google Colab, NVIDIA T4 GPU; TensorFlow 2.21.0 (Abadi et al., 2016), scikit-learn 1.6.1 (Pedregosa et al., 2011) |

Table: Table 4. Standardised experimental configuration

The notebook writes every result as data: one row per model in a results table, a classification report and confusion matrix per model, per-epoch training histories and per-image predictions. The trained models and logged results are published on Hugging Face (Kavishka, 2026). Training was made resumable through per-epoch checkpoints because Colab sessions can disconnect. The custom CNN was resumed twice, and its history file records 19 of the 20 scheduled epochs; the model saved at the end of the schedule was used for evaluation.

## 3.5 Model Architectures

### 3.5.1 Custom CNN

The custom CNN (Figure 4, Listing 1) has four convolutional blocks. Each block has a 3 × 3 convolution with ReLU activation followed by 2 × 2 max pooling; the blocks have 32, 64, 64 and 64 filters. The feature maps are flattened and passed to a 256-unit dense layer, dropout of 0.5 and a four-way softmax output. The 256-unit dense layer is also the feature layer used by the classical classifiers when the same architecture is trained at 128 × 128 pixels.

![Figure 4. Architecture of the custom CNN](paper_assets/figures/fig_arch_cnn.png){width=6.3in}

```python
# Listing 1. Custom CNN (shared by the 256-pixel classifier and the 128-pixel feature extractor)
def build_cnn(size, feat_name="dense"):
    m = models.Sequential([
        layers.Input(shape=(size, size, 3)),
        layers.Conv2D(32, (3, 3), activation="relu"), layers.MaxPooling2D((2, 2)),
        layers.Conv2D(64, (3, 3), activation="relu"), layers.MaxPooling2D((2, 2)),
        layers.Conv2D(64, (3, 3), activation="relu"), layers.MaxPooling2D((2, 2)),
        layers.Conv2D(64, (3, 3), activation="relu"), layers.MaxPooling2D((2, 2)),
        layers.Flatten(),
        layers.Dense(256, activation="relu", name=feat_name),  # 256 deep features
        layers.Dropout(0.5),
        layers.Dense(4, activation="softmax", name="predictions"),
    ])
    m.compile(optimizer="adam", loss="sparse_categorical_crossentropy", metrics=["accuracy"])
    return m
```

### 3.5.2 InceptionV3 and Xception

Both networks were loaded with ImageNet weights and without their original classification layers (Szegedy et al., 2016; Chollet, 2017). The convolutional backbone was frozen, so only the new layers were trained. Two heads were used (Listing 2):

- **Standalone classifier (256 × 256):** global average pooling followed by a four-way softmax layer.
- **Feature extractor (128 × 128):** flatten, a 256-unit ReLU dense layer (the feature layer, named `dense_2` for InceptionV3 and `dense_3` for Xception), dropout of 0.5 and a four-way softmax layer.

```python
# Listing 2. Pretrained backbones with new task-specific heads
def _base(kind, size):
    App = tf.keras.applications.InceptionV3 if kind == "inception" else tf.keras.applications.Xception
    b = App(input_shape=(size, size, 3), weights="imagenet", include_top=False)
    b.trainable = False                                        # ImageNet backbone is frozen
    return b

def build_transfer_standalone(kind, size=256):                 # standalone classifier
    base = _base(kind, size)
    x = layers.GlobalAveragePooling2D()(base.output)
    out = layers.Dense(4, activation="softmax")(x)
    return Model(base.input, out)

def build_transfer_extractor(kind, feat_name, size=128):       # feature extractor
    base = _base(kind, size)
    x = layers.Flatten()(base.output)
    x = layers.Dense(256, activation="relu", name=feat_name)(x)
    x = layers.Dropout(0.5)(x)
    out = layers.Dense(4, activation="softmax")(x)
    return Model(base.input, out)
```

### 3.5.3 Classical Classifiers

Four classical classifiers from scikit-learn (Pedregosa et al., 2011) were used (Listing 3): Random Forest with 100 trees (Breiman, 2001), Decision Tree (Quinlan, 1986), an SVM with an RBF kernel and probability outputs (Cortes and Vapnik, 1995) and, for the raw-pixel baseline only, Logistic Regression. They were trained on two kinds of input:

- **Raw pixels:** 256 × 256 greyscale images flattened to 65,536 values.
- **Deep features:** the 256 activations of the feature layer of each 128-pixel extractor (custom CNN, InceptionV3, Xception), computed for all 5,600 training images and 1,600 test images.

For each input, the Random Forest, Decision Tree and SVM were combined in a soft-voting ensemble that averages their class probabilities.

```python
# Listing 3. Classical classifiers and their soft vote
specs = {"rf":  RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1),
         "dt":  DecisionTreeClassifier(random_state=42),
         "svm": SVC(probability=True, random_state=42)}          # RBF kernel by default
for key, clf in specs.items():
    clf.fit(X_train, y_train)
probs = sum(specs[k].predict_proba(X_test) for k in ["rf", "dt", "svm"]) / 3
soft_vote_prediction = np.argmax(probs, axis=1)
```

### 3.5.4 Six-Predictor Majority and Confidence-Weighted Ensemble

The final ensemble (Figure 5) combines six predictors, each of which outputs a probability vector over the four classes:

1. Custom CNN (256 px);
2. InceptionV3 (256 px);
3. Xception (256 px);
4. soft vote of RF, DT and SVM on custom-CNN features;
5. soft vote of RF, DT and SVM on InceptionV3 features;
6. soft vote of RF, DT and SVM on Xception features.

Two combination rules were compared (Listing 4). **Majority voting** gives each predictor one vote for its top class; the class with most votes wins, and ties are resolved in favour of the lower class index. **Confidence-weighted voting** sums the six probability vectors and selects the class with the largest total, so that confident predictors carry more weight. The share of the summed probability held by the winning class is reported as the ensemble confidence.

![Figure 5. Six-predictor ensemble](paper_assets/figures/fig_arch_ensemble.png){width=6.0in}

```python
# Listing 4. Majority and confidence-weighted voting over the six predictors
P = np.stack(probs)                          # shape (6, n_images, 4)
summed = P.sum(axis=0)
pred_confidence_weighted = summed.argmax(axis=1)
ensemble_confidence = summed.max(axis=1) / summed.sum(axis=1)

votes = P.argmax(axis=2)                     # shape (6, n_images)
pred_majority = np.array([np.bincount(votes[:, i], minlength=4).argmax()
                          for i in range(votes.shape[1])])
```

## 3.6 Evaluation Metrics

All models were evaluated once on the 1,600 test images with the following metrics, where TP, FP and FN are the true positives, false positives and false negatives of a class:

| Metric | Formula | What it shows |
|---|---|---|
| Accuracy | correct predictions ÷ all predictions | Overall share of images classified correctly |
| Precision (per class) | TP ÷ (TP + FP) | When the model predicts a class, how often it is right; low precision means false alarms |
| Recall (per class) | TP ÷ (TP + FN) | How many images of a class the model finds; low recall means missed tumours |
| F1-score (per class) | 2 × precision × recall ÷ (precision + recall) | Balance of precision and recall |
| Macro precision / recall / F1 | Mean of the four per-class values | Average performance with every class weighted equally |
| Confusion matrix | Counts of true class against predicted class | Which classes are confused with which |
| ROC curve and AUC (one-vs-rest) | True-positive rate against false-positive rate across thresholds | Ranking quality of the predicted probabilities for each class |
| Precision-recall curve and average precision | Precision against recall across thresholds | Ranking quality with emphasis on the positive class |

Table: Table 5. Evaluation metrics

Because every class has 400 test images, macro recall equals accuracy. Per-class recall is the most clinically important measure here, because a missed tumour (a false negative) is more harmful than a false alarm.

## 3.7 Grad-CAM and EAA-IoU Formulation

### 3.7.1 Grad-CAM

Grad-CAM (Selvaraju et al., 2017) explains a prediction for class *c* by using the last convolutional layer, whose *K* feature maps *A^k* still have a spatial layout. Let *y^c* be the pre-softmax score of class *c*. The weight of feature map *k* is the average gradient of the score over the map, and the heatmap is the positive part of the weighted sum of the maps:

$$\alpha_k^c = \frac{1}{Z}\sum_i\sum_j \frac{\partial y^c}{\partial A_{ij}^k}, \qquad L^c_{\text{Grad-CAM}} = \mathrm{ReLU}\Big(\sum_k \alpha_k^c A^k\Big)$$

Each map was scaled to the range 0 to 1 and resized to 256 × 256 pixels. The target layers were the last convolutional layer of the custom CNN, `mixed10` for InceptionV3 and `block14_sepconv2_act` for Xception. Maps were always computed for the class predicted by the confidence-weighted ensemble, so that all three networks explain the same decision. The pre-softmax score was used because softmax outputs saturate for confident models and produce vanishing gradients.

One implementation detail matters for the custom CNN. Its convolutional output is flattened and passed to dense layers, so averaging the gradients over the map discards their spatial pattern. For this network the gradients were therefore multiplied with the activations at each location before summing over the channels, as recommended by Draelos and Carin (2020) for networks without global average pooling. For InceptionV3 and Xception, which end in global average pooling, this gives exactly the same map as standard Grad-CAM.

### 3.7.2 Ensemble Attention Agreement (EAA-IoU)

EAA-IoU measures whether the three architecturally different networks attend to the same region of an image. It needs no tumour outlines drawn by a radiologist, so it can be computed for every image, including new uploads in the web application. For an image, it is calculated in five steps (Listing 5):

1. Compute the Grad-CAM maps of the CNN, InceptionV3 and Xception for the ensemble's predicted class, each scaled to 0 to 1.
2. Binarise each map at threshold *t* = 0.5, giving a mask of the region the network considers important.
3. For each of the three pairs of networks, count the pixels in both masks (intersection) and in at least one mask (union).
4. Divide the intersection by the union to obtain the pair's IoU, which ranges from 0 (no overlap) to 1 (identical regions).
5. Average the three pairwise IoUs:

$$\text{EAA-IoU} = \tfrac{1}{3}\big[\mathrm{IoU}(M_{\text{CNN}}, M_{\text{Xcp}}) + \mathrm{IoU}(M_{\text{CNN}}, M_{\text{Inc}}) + \mathrm{IoU}(M_{\text{Xcp}}, M_{\text{Inc}})\big], \quad \mathrm{IoU}(A,B)=\frac{|A\cap B|}{|A\cup B|}$$

```python
# Listing 5. Pairwise IoU of binarised heatmaps and the EAA-IoU score
def iou(a, b, t=0.5):
    A, B = a >= t, b >= t
    union = np.logical_or(A, B).sum()
    return float(np.logical_and(A, B).sum() / union) if union > 0 else 0.0

cls = pred["pred_confidence_weighted"].values          # explain the ensemble decision
maps = {name: gradcam_batch(model, X, cls) for name, model in deep_models.items()}
pairs = [iou(maps["CNN"], maps["Xception"]), iou(maps["CNN"], maps["InceptionV3"]),
         iou(maps["Xception"], maps["InceptionV3"])]
eaa_iou = float(np.mean(pairs))
```

EAA-IoU was computed for all 1,600 test images. Its value as an error signal was evaluated by comparing correctly and incorrectly classified images, by the area under the ROC curve when low EAA-IoU is used to predict an error, and by the share of images flagged and errors caught at different thresholds. The ensemble confidence was evaluated in the same way as a reference signal.

## 3.8 Streamlit Application Design

The clinical decision-support prototype was built with Streamlit, which turns a Python script into an interactive web page. It has five pages: a home page with the research overview and key results, a performance page, a **Live Diagnosis** page, an XAI analysis page and a model comparison page. The Live Diagnosis page implements the full pipeline for one uploaded image (Figure 6):

1. **Upload** a JPG or PNG MRI slice.
2. **Predict** with all six predictors and combine them by confidence-weighted voting.
3. **Explain** the predicted class with Grad-CAM for the CNN, Xception and InceptionV3, and build a consensus heatmap as the confidence-weighted average of the three maps.
4. **Check agreement** by computing the three pairwise IoUs and EAA-IoU.
5. **Present** the predicted class, the ensemble score, the class probability distribution, the three heatmaps and the consensus map, the pairwise IoUs, the per-model vote breakdown and a full probability table.
6. **Escalate** with a prominent alert when EAA-IoU falls below 0.10, and report strong agreement when it is 0.20 or more (thresholds calibrated in Section 5.3).

The prediction and explanation functions are shared with the project's API back end, so the Streamlit page and the API give the same result for the same image. Models are loaded once and cached, and the page states on every result that the tool is for research and does not replace a radiologist.

## 3.9 Ethical Considerations

- **Data.** The dataset is public and anonymised, contains no personal identifiers, and was used under the terms of its Kaggle page. No attempt was made to re-identify any individual, and no new patient data were collected. No human participants took part.
- **Clinical safety.** The system is presented as decision support only. Every result page carries a warning that it must not be used for diagnosis, and the escalation alert directs uncertain cases to a radiologist rather than hiding them.
- **Bias and fairness.** The dataset has no demographic or scanner information, so performance across patient groups or hospitals cannot be assessed. This is stated as a limitation (Section 6.3).
- **Transparency.** Heatmaps are presented as indications of where the models looked, not as proof of correct reasoning, in line with the cautions of Ghassemi, Oakden-Rayner and Beam (2021).
- **Data management.** Data, models and results are stored in access-controlled accounts and will be retained only for as long as required by the university, then deleted, as set out in the Interim Report.
